# UX/UIガイドライン

Mahjo の見た目と操作感の正。トンマナ（どんな空気で見せるか）から、色・文字・形・部品の決まり、実装（CSS トークン）までを上から順に書く。上の章ほど判断の拠り所で、下の章ほど具体的な手段。迷ったら上の章に戻って決める。

- 機能仕様（画面・シーン・表示要素・操作）は [screens.md](./screens.md)。本書は「どう見せる・どう感じさせるか」。
- 実装の層の分け方（レイアウトは TSX・装飾は CSS、キャラ固有 SVG の resolver）は [architecture §5](./architecture.md)。本書はその「装飾」側の中身を決める。
- キャラの identity（テーマ色・差し色・モチーフ）の定義は [character-guide §2](../characters/character-guide.md)。本書はそれを画面でどう受けるかを書く。
- 未確定の指針には TBD を付す（実装で確定したら本書に反映する）。
- 値の正本：本書は色・文字・形の「役割」と「トークン名」を決める。具体の値は `src/ui/index.css` の `:root` が正で、本書の値は写し（[architecture](./architecture.md)「正本の規約」のチューニング値と同じ扱い）。

## 1. トンマナ

### 1.1 ひとことで

夜の占い館で、相棒の占い師と一緒に牌を読む。静かで、やわらかく灯っていて、少しだけ神秘的。

世界観（[world.md](../characters/world.md)）は「運河沿いの中華風の町・赤提灯の夜市・牌は神聖な占術の道具・魔女と使い魔」。画面はその「夜」と「灯り」を借りる。舞台装置を描き込むのではなく、空気だけを持ち込む。

### 1.2 キーワード

| 寄せる | 避ける |
|---|---|
| 夜・紫紺の空・灯り（金・キャラ色のにじみ） | 真っ黒・真っ白のフラット画面 |
| やわらかい・落ち着いた・余白がある | ギラギラ・ネオン・ゲーミング風の発光 |
| 静かな高揚（ひらめき・お祝いは一瞬だけ光る） | 点滅・揺れ・急かすカウントダウン |
| 手ざわり（牌・点棒・御札＝実物の所作で見せる） | テキストのバッジや記号だけで状態を表す |
| キャラがそばにいる（声・表情・色が画面に溶ける） | ストイックな問題集・試験の答案用紙の見た目 |

### 1.3 声の分担

- 画面の文章のうち、人格を持つ言葉はキャラが話す（会話枠）。誤答の理由・ヒント・解説はキャラの声（[character-guide §2](../characters/character-guide.md)「セリフ」）。
- UI の文言（ボタン・見出し・設定項目）は短く中立。キャラ口調を混ぜない（キャラを切り替えても UI は同じ）。
- 難しい漢字語にはカナの読みを添える（[character-guide §2](../characters/character-guide.md) の読みルール）。

## 2. 見た目の原則

トンマナを判断に落とした決まり。新しい画面・部品で迷ったらここで決める。

1. プレッシャーをかけない（[product-concept §3](../product-concept.md)）。誤答で画面を赤くする・揺らす・警告音を鳴らす等の「採点された」演出はしない。正誤は4択パネルの色とキャラの表情・セリフだけが担う。強い演出はお祝い（ポジティブ）側にだけ、一瞬使ってよい。
2. 牌がいちばん読みやすい。盤面（牌エリア）の上に装飾・グロー・半透明パネルを重ねない。背景のグラデやグローは低アルファに留め、白い牌面とのコントラストを守る。
3. 共通の器、キャラが注ぐ色。アプリ共通の色は無彩色寄りの「器」（背景・面・枠・文字）だけを持つ。個性の色（テーマ色・差し色）は選択中キャラから流し込む。共通の器にキャラの具体色を書かない。
4. 状況では色を変えない。テーマ色・背景グローは画面・状況をまたいで一定（誰と学んでいるかの identity）。
5. 実物で見せる。リーチは千点棒、選択は御札、のように、記号より卓上の所作・キャラの法具で見せる（§7）。
6. 操作の場所はぶれない。メイン画面の操作は会話枠の右下に集約（ノベルゲームの送り位置）。回答前後で盤面の要素を増減させず、手牌を動かさない。

## 3. 色

### 3.1 パレットの役割

色は「役割」で名前を付けて使う。下表の役割の外に新しい色が要るときは、まず既存の役割で足りないかを考え、足りなければ役割ごと本表に追加する。

| 役割 | 用途 | 現在の値 | トークン |
|---|---|---|---|
| 背景（下） | 画面のベース。真っ黒は使わない | `#15121f` 濃い紫紺 | `--color-bg` |
| 背景（上） | 対角グラデの上端・モーダルの面 | `#221c3a` | `--color-bg-top` |
| 面（パネル） | 情報箱・一覧・会話枠など背景に浮く面。色は1つ、濃さ（α）で段を付ける（§5.3） | `rgb(18 20 28)`＋α | `--panel-rgb`（案） |
| 枠（パネル） | 面の縁・区切り線 | `#3b3f4d` | `--panel-border`（案） |
| 本文 | 標準の文字 | `#f2f2f2` | `--color-text` |
| 文字・弱1 | 値・補足（本文に近い） | `#c8ccd6`（`#c8cdd8` と統合） | `--text-soft`（案） |
| 文字・弱2 | ラベル・注記 | `#9aa3b2` | `--text-muted`（案） |
| 文字・弱3 | いちばん控えめ（単位・脚注） | `#8a93a3` | `--text-faint`（案） |
| ボタン面 | 通常ボタンの面（通常→ホバー） | `rgba(60,66,82,.9)` → `rgba(74,82,102,.96)` | `--btn-bg`／`--btn-bg-hover`（案） |
| ボタン枠 | 通常ボタンの縁（通常→ホバー） | `#5a6172` → `#79808f` | `--btn-border`／`--btn-border-hover`（案） |
| 進む操作 | 会話枠の「次へ」等・名札 | `#c7506a`（ホバー `#d0688a`） | `--action-bg`／`--action-bg-hover`（案） |
| カード | 紫のカード（キャラカード・立ち絵の代わり） | グラデ `#3a3550`→`#211f2e`・枠 `#4a4663`・文字 `#b9b3d4` | `--card-bg`／`--card-border`／`--card-text`（案） |
| ハイライト | 解説・ヒントで光らせる・お祝いの金 | `#f5c451` やわらかい金 | `--color-highlight` |
| バッジ | 状況の小バッジ（第一打・一発 等） | 面 `#e2c44e`・文字 `#1a1a1a` | `--badge-bg`／`--badge-text`（案） |
| 正解 | 4択の正解 | `#2e7d32` 緑 | `--color-correct`（案） |
| 不正解 | 4択の選んだ誤答 | `#c62828` 赤 | `--color-wrong`（案） |
| テーマ色 | 選択中キャラの主色。背景グロー・符系バッジ・選択枠 | キャラが注ぐ（既定 `#6a4fb0`） | `--char-glow` |
| 差し色 | 選択中キャラの従色。タイトル文字・星・装飾 | キャラが注ぐ（未指定は `--color-highlight`） | `--char-accent` |

- （案）は refactoring-11 で `:root` に導入するトークン名。導入までは各 CSS に直値で書かれている。
- 進む操作のピンク `#c7506a` はいまキャラに依らず固定。キャラのテーマ色に寄せるかは TBD（テーマ色は背景グローと同系色になり、ボタンが背景に沈むおそれがある）。

### 3.2 正誤の色

正解＝緑・不正解＝赤は、4択ボタンの面と枠だけに使う。背景・会話枠・キャラには波及させない（§2-1）。赤は「選んだ誤答」1つにだけ付き、正解の緑と並んで「どこが答えだったか」を示す情報として出す（叱るための赤ではない）。

### 3.3 牌の色（別系統）

牌の色は UI の色とは別の意味体系（麻雀の伝統色）として、牌のスコープ（`.tile`。`TileSvg.css`）に閉じて持つ。

- 牌面 `--tile-face` 生成り `#f7f4ea`・縁 `--tile-edge`・漢字書体 `--tile-kanji-font`（明朝）。
- 墨 `--ink`：萬子の漢数字・風牌＝濃紺／索子・發＝緑／萬の字・中＝赤。筒子の丸 `--pip-blue`／`--pip-red`。赤ドラは `--pip-red`。
- 正解の緑・不正解の赤と値が一致していても、共通トークンに束ねない（意味が違う。片方を変えたら他方が変わる事故を防ぐ）。

### 3.4 キャラの色の流し方

- テーマ色・差し色は App が選択キャラの値を `--char-glow`／`--char-accent` に流す（[character-guide §2](../characters/character-guide.md)「テーマ色」「差し色」）。
- 部品側はキャラの色を直接知らない。`color-mix(in srgb, var(--char-glow) N%, transparent)` のように器のトークン経由で使う。
- キャラの世界観に属する装飾の色（御札の朱・墨、鈴の銀、月・蝶のモチーフ）は、共通トークンに吸い上げず各キャラの CSS（`src/ui/character/**`）に閉じる。キャラ追加で `:root` を編集しない。

## 4. タイポグラフィ

### 4.1 書体

- UI・本文：システムのゴシック（`system-ui, -apple-system, 'Segoe UI', 'Hiragino Kaku Gothic ProN', 'Noto Sans JP', sans-serif`）。Web フォントは読み込まない（軽さ・オフライン）。
- 牌の漢字：明朝（`--tile-kanji-font`）。牌だけの書体で、UI には使わない。
- 行間は本文 1.6、会話文 1.7（読ませる文章はやや広く）。

### 4.2 文字サイズの段

画面幅で伸び縮みさせる（`clamp(最小, vw, 最大)`）。現状の値を段に整理したもの。段の外のサイズを足す前に、近い段に寄せられないか考える。

| 段 | 用途 | 現在の値 |
|---|---|---|
| タイトル | スタート画面のロゴ文字 | `clamp(2.6rem, 6vw, 4.2rem)` |
| 見出し | オーバーレイの題・結果の点数 | `clamp(1.1rem, 2vw, 1.4rem)` 前後 |
| 会話 | 会話枠の本文（いちばん読ませる文字） | `clamp(0.95rem, 0.6rem + 0.9vw, 1.3rem)` |
| 操作・大 | メニュー項目・4択 | `clamp(1rem, 1.6vw, 1.2rem)` 前後 |
| 操作・小 | 戻る・ヒント・次へ | `clamp(0.85rem, 1.4vw, 1.05rem)` 前後 |
| 本文・一覧 | 一覧・表・設定項目 | `clamp(0.85rem, 1.5vw, 1rem)`／`clamp(0.8rem, 1.4vw, 0.95rem)` |
| 注記 | バッジ・名札・脚注 | `clamp(0.65rem, 1.1vw, 0.85rem)` 前後 |

- 段の名前でトークン化するか（`--fs-body` 等）は TBD。いまは近い値が微妙に違うものが混ざっているので、まず段に寄せる。
- 太さ：見出し・ボタン・ラベルは 700、タイトルだけ 800。本文は標準。太さで強調しすぎない（全部太字になると何も目立たない）。
- 字間：タイトル・短いラベルだけ少し空ける（0.04〜0.1em）。本文は空けない。

## 5. 形

### 5.1 角丸

| 形 | 値 | 使う所 |
|---|---|---|
| ピル | `999px` | 小さく押すもの（戻る・ヒント・次へ）・バッジ・名札 |
| 中 | `0.7〜0.8rem` | ボタン（メニュー・4択）・カード・一覧の箱 |
| 大 | `0.9〜1rem` | 会話枠・オーバーレイの大きな面 |
| 牌 | `10px` | 牌（SVG の viewBox 基準） |

尖った角（0）は全画面シート（モバイルのオーバーレイ）だけ。

### 5.2 余白

rem 基準。部品の内側は `0.35〜1.2rem`、要素間の gap は `0.3〜1rem` の範囲で、画面外周は `%`／`vh`／`clamp` の相対値。刻み（スケール）を決めてトークン化するかは TBD（現状は部品ごとの手書き値）。

### 5.3 面の濃さ（パネルの段）

面は同じ色（`--panel-rgb`）の濃さだけを変えて段を付ける。濃いほど手前。

| 段 | α | 使う所 |
|---|---|---|
| 薄 | 0.5 | 一覧の中の入れ子の箱 |
| 標準 | 0.6 | 情報箱・表・一覧 |
| 濃 | 0.92〜0.94 | 会話枠・メニューのドロップダウン（読ませる・重なる面） |

### 5.4 影

影は浮いている物にだけ付ける（平面の箱には付けない）。

| 段 | 値 | 使う所 |
|---|---|---|
| 牌 | `drop-shadow(0 1px 2px rgba(0,0,0,.45))` | 牌 |
| 浮き | `0 0.4〜0.5rem 1.2〜1.5rem rgba(0,0,0,.4〜.45)` | 会話枠・ドロップダウン |
| モーダル | `0 1rem 3rem rgba(0,0,0,.5)` | オーバーレイのパネル |
| 発光 | `0 0 Nrem <色>` | ハイライト・選択中（影でなく光。§7.3） |

### 5.5 動き

| 種類 | 時間 | 使う所 |
|---|---|---|
| ホバー | 0.12s ease | ボタンの面・枠の色 |
| 出入り | 0.15〜0.16s ease | 御札が乗る・トグル |

速く小さく。動きで注意を奪わない。演出としてのアニメ（お祝い等）は §8。

## 6. 部品

画面をまたいで同じ見た目で出る部品。新しい画面はまずここの部品で組む。

### 6.1 ボタン

| 種類 | 見た目 | 例 |
|---|---|---|
| 通常 | ボタン面＋ボタン枠。ホバーで面と枠が一段明るく | スタートのメニュー項目・ヒント・戻る |
| 進む | 進む操作のピンク・ピル・白文字 | 会話枠の「次へ」「はじめる」 |
| 4択 | 濃い面＋パネル枠。ホバーで一段明るく。選択で枠が明るくなり、答え合わせで正解＝緑・選んだ誤答＝赤 | 回答の4択 |
| アイコン | 透明＋パネル枠の正方形。ホバーで枠がテーマ色 | オーバーレイの戻る・閉じる |

- 押せない状態（回答後の4択）はホバーで色を変えない（正誤の色を消さない）。
- 選択の印はキャラの法具（まお＝御札）を被せる。中立の位置決めだけ部品が持ち、見た目はキャラ側（[architecture §5](./architecture.md)）。

### 6.2 パネル・情報箱

標準の面（α 0.6）＋パネル枠＋角丸 中。見出しは文字・弱3〜弱2、値は本文〜文字・弱1。

### 6.3 会話枠

ノベルゲーム風。濃い面（α 0.94）＋パネル枠＋角丸 大＋浮きの影。左上に名札（進む操作のピンク・ピル）、右上にヒントボタン、右下に操作ボタン。大きさは状況で変えない（中身はスクロール。[screens.md](./screens.md)・§9）。

### 6.4 バッジ

- 状況バッジ（第一打・一発）：バッジの金面＋黒文字・ピル。観測できる状況だけを書く（役名を書かない＝答えにしない）。
- 内訳バッジ（解説で積み上がる翻・符）：翻系＝ハイライトの金トーン、符系＝テーマ色トーン。いま説明中の1つだけ内側の縁取りと淡い発光。

### 6.5 カード

紫のカード（カードのグラデ＋カード枠＋カード文字）。キャラカード・立ち絵が無いときの代わり。選択中はテーマ色の発光。

### 6.6 オーバーレイ（参照系）

PC は中央モーダル（暗幕 `rgba(0,0,0,.55)`＋背景（上）の面＋角丸 1rem＋モーダルの影）、モバイルは全画面シート（角丸なし）。役一覧・点数表など。

## 7. 盤面の見せ方

### 7.1 牌の描画

- 牌は SVG で描画（Unicode 麻雀牌文字を使わない理由は [architecture](./architecture.md) §1）。手牌・副露・上がり牌・ドラ表示牌で再利用できるコンポーネントにする。
- 牌面は本物寄せ（萬子＝漢数字＋萬／筒子＝青赤のドーナツ／索子＝竹／白＝無地）。色は §3.3。
- 上がり牌は他と区別（位置を離す／ロンは浮かせて逆向き 等）。副露面子は横向き等で区別。
- 赤ドラ（赤5m/5p/5s）は色で区別表示。
- 看板牌（1筒/1索）はキャラ別の絵に差し替えられる（[architecture §5](./architecture.md)）。

### 7.2 場の状況（リーチ 等）

「自分の情報は手牌まわり」（自風と同じ自分エリア）にまとめる。フラグはテキストのバッジに頼らず、実物の所作・道具で見せることを優先する。

- リーチ：手牌の前（自分から見て卓の中央側＝画面では手牌の上側）に千点棒を1本、横向きに置いて表す（卓上の実際の所作どおり）。点棒も牌と同様に SVG で描画（白地に赤い点。Unicode は使わない）。`WinContext.riichi` に連動。
- ダブルリーチ：同じ千点棒で表し（供託は現実でも1本＝実物を嘘にしない）、リーチラベル脇に小バッジ「第一打」を添えて状況（いつ宣言したか）を示す。役名でなく観測できる状況を出すことで、学習者が「第一打のリーチ＝ダブルリーチ」と条件から役へ辿れるようにする（役名・確定値は答え側が開示）。役一覧のダブルリーチ行も同じバッジを鏡写しに出す。`WinContext.doubleRiichi` に連動。
- 一発：リーチラベル脇の小バッジ（「第一打」と同列。両方立てば 第一打 → 一発 の時系列順に並べる）。
- ツモ／ロン、海底・河底・嶺上・槍槓 等その他フラグの見せ方は実装時に確定（TBD）。
- ハイライト連携：採点で「リーチ」役をクリックしたとき千点棒を光らせたい。対応する `HighlightTarget`（[data-model](./data-model.md) §10）が必要になれば型側に追加する。

### 7.3 ハイライト

- 採点項目と対応要素を光らせる連携の動き自体は [screens.md](./screens.md) 解説シーン、光らせる対象データ（`HighlightTarget`）は [data-model](./data-model.md) §10。本書はその見た目。
- 光らせ方はやわらかく、答えを急がせない。ハイライトの金（`--color-highlight`）で、牌は縁を金にして淡い発光（`drop-shadow`）、文字は金色＋淡い `text-shadow`。点滅させない。
- 魔女キャラの「符（お札）を貼る」等のキャラ演出はペルソナ／描画側で乗せられる（対象データは中立）。

## 8. 演出・アニメ・フロー（TBD）

- クイズ：回答 → キャラのリアクション → 解説、の流れを気持ちよく（[screens.md](./screens.md)）。
- 正誤・節目の演出はお祝い止まりで、プレッシャーをかけない（§2-1）。音まわりは [sound.md](./sound.md)。
- 背景：画面全体に淡い対角グラデ（上やや明→下暗。`--color-bg-top`→`--color-bg`）を重ねて奥行きを出し、その上に選択中キャラのテーマ色で「立ち絵の背後＝画面左下のステージ帯」へ向けたラジアルグロー（＋右上に弱いアンビエント）を敷く。いずれも低アルファ（§2-2）。
- 装飾モチーフ：共通の星・きらめき＋キャラ固有モチーフ（まお＝月／りん＝蝶）。当面はスタート画面だけ（[character-guide §2](../characters/character-guide.md)「モチーフ」）。
- アニメ・演出の気持ちよさは人手で確認（[testing](../dev/testing.md) の人手領域）。

## 9. レスポンシブ（端末・向き対応）

横持ちを推奨、縦持ちはサポート（使えればよい・見やすさは犠牲を許容）。手牌は14牌横並びで横幅を要するため横向きが本命。回転を促すヒントは出さない（横持ちは使い慣れていれば自明とみなす）。

- 出し分けの軸（PC を巻き込まないため）：横持ちで縦が低い＝`max-height`（PC モニタも幅>高さで landscape 判定になるため `orientation` だと PC を巻き込む。縦が低いのは横持ちスマホ固有なので height で線を引く）。縦持ち＝`orientation: portrait`（PC・横持ちは landscape 判定で該当しない）。いずれも「低い／狭い画面用のルールを追加」する形にし、PC・横持ち base の CSS は据え置く（既存の見た目を崩さないことを最優先）。
- メイン（クイズ）：手牌が4択に重ならないことを最優先（盤面は潰さずスクロールに化けるフォールバック）。横持ちはキャラの取り分を減らして盤面に高さを回す。縦持ちは手牌を2段に折り返し、場情報バーは中央寄せをやめ左寄せ、立ち絵は非表示にして会話枠を全幅にする。
- 会話枠（ノベル風）：大きさは状況（解説バッジの有無など）で変えず一定に保つ（PC と同じ）。あふれる本文は枠内スクロール、操作ボタンは枠基準で固定。
- スタート／設定：入りきらないときはスクロールで全項目に届かせる（1画面に詰め込まない）。立ち絵の幅は `--standee-min`〜`--standee-max` で伸び縮みし、下限に達する幅（54rem）で2段（縦積み）に切り替える。

## 10. 実装

### 10.1 トークンの置き場

| 範囲 | 置き場 | 例 |
|---|---|---|
| アプリ共通（中立な器） | `src/ui/index.css` の `:root` | 背景・面・枠・文字・ボタン・ハイライト・正誤 |
| キャラが注ぐ色 | App が `:root`（または画面の根）に上書きで流す | `--char-glow`・`--char-accent` |
| 部品専用 | その部品のルートクラスにスコープ | 牌（`.tile` の `--tile-face`・`--ink`） |
| キャラ固有の装飾 | `src/ui/character/**` の各 CSS | 御札の朱・鈴の銀・月・蝶 |

部品専用のトークンを複数の部品で使いたくなったら、そのとき `:root` へ昇格する。

### 10.2 命名

- 役割で名付ける（`--panel-border`・`--text-muted`）。色名（`--gray-500`・`--purple`）では名付けない。値を変えても名前が嘘にならないように。
- 状態は接尾辞で（`-hover`・`-current`）。
- 既存の `--color-*` はそのまま残す（`--color-bg`・`--color-text`・`--color-highlight`）。新しく足すものは役割名を先頭に（`--panel-*`・`--text-*`・`--btn-*`・`--card-*`・`--badge-*`）。

### 10.3 書き方の決まり

- 色の直値は書かない。`:root`・部品スコープ・キャラ CSS のトークン定義の中だけに書く。例外は牌の SVG 幾何のように意味を持たない一回限りの値（コメントで理由を残す）。
- 濃さ違いは `rgb(var(--panel-rgb) / α)` で、キャラ色の薄め・混ぜは `color-mix(in srgb, var(--char-glow) N%, transparent)` で作る（新しいトークンを増やさない）。
- SVG の `fill`／`stroke` は属性に焼き込まず CSS クラスで当てる（[architecture §5](./architecture.md)）。
- 共通クラスにまとめるのは、意図が名前で読めるときだけ（例 `.subscreen`）。見た目が似ているだけで別の意味の部品は、トークンを共有してもクラスは分けたままにする（[architecture](./architecture.md) 冒頭の指針）。
- ユーティリティ CSS（Tailwind 等）は使わない（[decisions.md](../decisions.md) 2026-06-06）。
